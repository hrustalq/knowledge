A rail of sections, grouped by what they act on: **Connect AI** is yours
(keys, client configs, the skill — see the MCP server article) and open to every role; the
rest are the workspace's and need a workspace admin to change. Everything here is an **override of a code default**: `null` means inherit the
`ASSISTANT_*` environment variable, so an empty configuration reproduces the pre-settings
behaviour exactly, and a release can still improve a shipped prompt for workspaces that
never touched it.

## Providers and models

A provider is a connection: base URL, credential, budget. `openai-compatible` covers
OpenAI, Ollama, LM Studio and vLLM; `deepseek` and `gen-api` only pre-fill a base URL.

A model is something a provider serves, named by the code its API knows it under. **Fetch
models** asks the provider for its list and adds the ones you tick. Many servers have no
list, so you can also type a code name. Price and capabilities belong to the model.

Which model serves a call is first usable hit:

```
thread pin  →  agent pin  →  purpose route (chat / review / extraction)  →  inline config  →  env
```

A workspace with no models behaves exactly as it did before models existed. A removed model,
or one whose provider is off, falls through to the next source rather than failing the call.

**Settings → AI → Configuration** lists them all in one place. The inline config is the
pinned **Default** row, every provider follows it, and **Add provider** is the last row. Each
provider shows its endpoint and where its key comes from, with its models beneath it: the
work each one serves, its price, and whether it is **In chat**. **Test** checks that provider,
not whatever chat happens to be routed at. Choose which model runs what under **Routing**,
which appears once there is a model to route to.

**Enabled** on a provider's row hides all its models from every picker. Pins at them are kept,
and take effect again when it is back on. The chat picker lists every **In chat** model of
every enabled provider. An agent or a route can still use a model that is not in chat.

Each model has its own price per 1M tokens, in USD or rubles. Leave it empty to use the
built-in list price for known models. A model with no price at all says so on its row, and
its calls show no cost in Usage.

Credentials are AES-256-GCM encrypted, write-only over the API (you see whether one is set
and its last four characters). Without `SETTINGS_ENCRYPTION_KEY` secret *writes* are
disabled; an undecryptable row falls back to the environment credential.

## Agents

A named actor: instructions, tool allowlist, model, output contract. Ten are built in —
`router`, `researcher`, `author`, `reviewer`, `drafter`, `planner`, `extractor`,
`glossarist`, `transcriber`, `curator` — covering every model call site in the product. A
custom agent may not shadow a built-in name.

Two rules matter:

- **The tool allowlist intersects, never unions.** A settings row cannot widen what a
  model reaches.
- **The router is deterministic first.** Capability, budget and enablement are decided in
  code; the model only breaks ties between candidates that already passed. An LLM picking
  the model would itself be a call somebody had to pick a model for. Rejections are
  recorded with their reason.

`curator`, `reviewer` and `glossarist` can run in the background, on a schedule. A run
must have an owner: it rehydrates a real principal and passes the same access checks an
HTTP request would. Findings become changes through **Propose**, which runs the drafter
and opens a merge request attributed to *you*, not to the run's owner — merging is your
act.

## Skills

Instruction packs appended to the system prompt, matched by explicit selection or trigger
words. Capped at 3 per turn and 8k characters.

## Plugins

External MCP servers. Their tools are namespaced `mcp__<slug>__<tool>` so they can never
shadow a built-in, and their output is wrapped as **untrusted data**. Plugin URLs are
DNS-resolved and refused on private, loopback, link-local and carrier-grade NAT ranges
unless `AI_PLUGINS_ALLOW_PRIVATE_URLS` is set — an SSRF guard, since the server is the one
making the request.

## Budgets and usage

Budgets are checked before each call, not reserved, and are opt-in per workspace. Over
budget returns **429** with a specific error code rather than a generic failure.

Every upstream call writes one usage row — tokens, cost, operation, provider, user — which
serves both the usage charts and the call log. Prompt and completion text is *not* stored
there; that lives with the conversation.
