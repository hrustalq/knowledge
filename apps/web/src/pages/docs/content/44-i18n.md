# Languages

English and Russian, English the default and the fallback everywhere.

## What is translated, and what is not

**The product is translated. Your content is not.** A page's text, a comment, a glossary
definition — those are yours, and translating them would change what they say. Only the
interface around them changes language.

Two model calls deliberately ignore the locale, for the same reason:

- **OCR** must match the image, so its prompt forbids translating.
- **Relation extraction** emits stable graph keys like `service:identity`; localizing them
  would fragment the graph into one set of entities per language.

## How the language is resolved

```
?lang=   →   kn_lang cookie   →   Accept-Language   →   default
```

on both the API and the app. The cookie beats the header because the header is the
browser's default, while the cookie is a decision someone made in this product.

The durable home is `users.locale`, mirrored into the cookie so the **server-rendered
pass** already knows the language — a cookie is the only thing readable before any
JavaScript runs.

Background work carries its own frozen locale: an import job and a workflow run each
record the language they started in, so a job that finishes tomorrow still speaks the
language of the person who started it.

Change it from the language switcher in the top bar, or `PATCH /v1/me`.

## A note for translators

Sentences are translated whole, never assembled from fragments — Russian needs
grammatical cases that an English fragment does not carry. Counts use proper CLDR plurals
(Russian has four forms, and 11–14 are "many" despite ending in 1–4).

Russian text runs 15–20% longer than English, so a few hints are shortened in Russian
rather than the layout being widened for every language to fit one.
