# Web performance baseline — 2026-11-18

Baseline for [#1241](https://github.com/hrustalq/knowledge/issues/1241), measured on `origin/dev` `aacbe0cd` plus this issue's measurement tooling. No performance fix is included.

## Method

- **Build:** production Vite 8.2.2 client and SSR builds, served by `server.js` on port 5175. The audit harness forwards `/api` to the local API, the job Caddy performs in production.
- **Machine:** Apple M3 Pro, arm64, Node 26.4.0, Chrome 157.0.8103.79.
- **Fixture:** an existing 95-page local project, plus a 163,782-byte document with 150 sections and 750 paragraphs. The public reader opens a share of that document. No fixture page contains Mermaid.
- **Browser numbers:** median of three cold runs. Cache and service workers are disabled. Route prefetch is disabled with Save-Data so JS belongs to the requested route, not speculative navigation.
- **Profiles:** desktop is 1440×900 with no CPU/network throttle. Mobile is 390×844, 4× CPU slowdown, 1.6 Mbps down, 750 Kbps up and 150 ms RTT.
- **LCP / CLS:** browser Performance Observers. **INP:** Event Timing after a route-specific click or keyboard interaction; this is a lab interaction measurement with a 16 ms event floor, not field INP or a 98th-percentile population.
- **Hydration:** the native `knowledge:hydration` User Timing measure around synchronous `app.mount`.
- **JS:** uncompressed same-origin script response bodies, including route code loaded on mount. CSS, fonts, API responses and speculative route prefetch are excluded.
- **SSR:** median of five warm calls to the built `entry-server.render` / `entry-public.render`. This includes `prefetchShell` and page rendering, but excludes HTTP, template splicing, compression and network transfer.

These are controlled local lab numbers, not production field data or an agreed latency SLO.

## Bundle analysis

`pnpm --filter @knowledge/web run analyze:bundle` writes the interactive `apps/web/dist/bundle-report.html` and the Vite manifest. It does not open a browser or alter chunking.

Largest client chunks from that build:

| Chunk | Raw KiB | Gzip KiB | Loaded by this baseline |
| --- | ---: | ---: | --- |
| `RichEditor` | 706.6 | 224.7 | Long document and editor |
| Mermaid parser shared chunk | 646.6 | 139.8 | No: the fixtures have no diagrams |
| Russian catalogue | 580.0 | 151.9 | No: English renders only |
| Cytoscape | 424.7 | 134.6 | All three `/documents` views |
| English catalogue | 339.9 | 116.0 | Member routes |

Neither eager entry graph (`index.html` or `reader.html`) contains Mermaid, the graph or the editor. Eagerness is route-level instead:

- `DocumentsListPage.vue` statically imports `GraphCanvas`, so graph code reaches tree and list as well as graph (#1279).
- The read view mounts the full rich editor, so a long read pays the editing cost (#1280).
- The public entry eagerly includes published-site search/Ask, export UI, search widgets and `vue-router` on a plain share link (#1281).
- Mermaid is split into lazy chunks. No audited route requested it because the fixtures deliberately contained no diagram.

### Initial-entry budget

`make check` now runs `make bundle-budget` after the build. The check sums exactly the script and modulepreload files in each generated HTML shell, without following dynamic imports.

| Entry | Baseline | Budget | Headroom |
| --- | ---: | ---: | ---: |
| member `index.html` | 786.8 KiB | 850 KiB | 63.2 KiB |
| public `reader.html` | 523.5 KiB | 575 KiB | 51.5 KiB |

The deliberate failure path was checked with a 1-byte member budget. The normal budget is a regression tripwire, not a claim that the current size is good; route-level costs above remain visible in this report.

## Reproduce

With the API running and the production web preview on port 5175:

```bash
pnpm --filter @knowledge/web run analyze:bundle
pnpm --filter @knowledge/web run build:server
make bundle-budget

PERF_WORKSPACE_ID=<workspace> \
PERF_PROJECT_ID=<project> \
PERF_DOCUMENT_ID=<long-document> \
PERF_SHARE_PATH=/s/<token> \
pnpm --filter @knowledge/web exec node scripts/measure-performance.mjs
```

Optional environment variables are `PERF_BASE_URL` (default `http://localhost:5175`), `PERF_API_URL` (default `http://localhost:3000`) and `PERF_RUNS` (default 3). Do not commit a live share token.
